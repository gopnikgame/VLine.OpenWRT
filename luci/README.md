# VPN Routing для OpenWrt

Отдельный пакет LuCI с двумя вкладками. Рассчитан на OpenWrt 24.10 с Lua 5.1 и штатной авторизацией LuCI.

- **Подключение** загружает подписку, сохраняет один ручной резерв VLESS и позволяет выбрать и проверить сервер. По умолчанию перехват отдельным экземпляром Xray охватывает TCP и UDP IPv4 всей `br-lan`.
- **Настройки** показывают состояние правил, действующий локальный DNS, охват LAN и HWID. Охват можно ограничить списком устройств. Веб-форма ручного импорта Happ и INCY использует тот же компилятор, что и CLI.

Предпросмотр доступен в сеансе LuCI пользователя root через POST с CSRF-токеном. Ссылка подписки видна в редактируемом поле и передаётся в теле запроса. Тела профилей остаются в памяти на время обработки. Предел URL-encoded запроса 96 КиБ выбран с запасом относительно лимита LuCI 24.10 в 100 КиБ. [Диспетчер LuCI 24.10](https://github.com/openwrt/luci/blob/openwrt-24.10/modules/luci-base/ucode/dispatcher.uc#L643-L675), [HTTP LuCI 24.10](https://github.com/openwrt/luci/blob/openwrt-24.10/modules/luci-base/ucode/http.uc#L15-L16)

## Сценарий подключения

1. «Получить серверы» показывает все поддерживаемые профили подписки отдельными строками. Выбранная строка выделена рамкой. Узел текущего подключения отмечен словом «Активный».
2. «Проверить все» последовательно отправляет HEAD через каждый сервер и обновляет статус у его строки. Ответ 2xx даёт «Доступен». Остальные HTTP-ответы, таймаут и отсутствие ответа дают «Недоступен». При ошибке самой проверки строка остаётся «Не проверен». Можно остановить очередь после текущего запроса или проверить один выбранный сервер.
3. «Подключить» сохраняет и применяет выбранный сервер. Чтобы перейти на другой узел той же подписки, выделите его и нажмите «Подключить». VPN Routing проверяет новый узел до переключения, удерживает защиту от прямого выхода и восстанавливает прежний узел при отказе применения. Успешный выбор используется после перезагрузки. Для отключения выберите активный сервер и нажмите «Отключить».

Сохранённая подписка обновляется на роутере каждые 6 часов. Служба procd делает первую попытку после запуска, повторяет обычные ошибки через 10 минут и использует тот же HWID и подтверждённый источник. Последний успешно полученный список доступен в LuCI. Если выбран сервер подписки и он получил новые параметры, VPN Routing проверяет их через HEAD и применяет с действующей защитой от прямого выхода. При сбое применения восстанавливается прежний профиль. При исчезновении узла или неоднозначном совпадении выбор сохраняется. Неизменившийся профиль работает без перезапуска Xray. [Супервизор OpenWrt procd](https://git.openwrt.org/project/procd/tree/README.md)

### Ручной резерв VLESS

Откройте «Резерв VLESS», задайте название и сохраните одну ссылку `vless://`. После отправки поле ссылки очищается. VPN Routing хранит ссылку в записи подключения, доступной root с режимом 0600. В списке отображаются название и отметка «Резерв». Выберите эту строку для проверки HEAD или подключения. Для изменения и удаления активного резерва сначала выберите сервер подписки или отключите VPN Routing.

Подписку и резерв можно использовать по отдельности. Переход между ними выполняется через явный выбор сервера и «Подключить». Таймер продолжает обновлять список HTTPS-подписки при активном резерве. После перезагрузки VPN Routing восстанавливает выбранный выход. Если кэш подписки потерян, в списке доступен последний успешно применённый сервер подписки.

Для этих действий используется собственный POST-обработчик VPN Routing. Общий LuCI Save & Apply применяет все ожидающие изменения сеанса. [Кнопки LuCI view](https://github.com/openwrt/luci/blob/openwrt-24.10/modules/luci-base/htdocs/luci-static/resources/luci.js#L1904-L1939), [применение UCI в rpcd](https://github.com/openwrt/rpcd/blob/openwrt-24.10/uci.c#L1511-L1543)

## Рабочее подключение

Для рабочего подключения нужны OpenWrt 24.10, Xray 26.10.31, скрипты TPROXY Manager 26.8.13-1, `ip-full`, `nftables-json`, `kmod-nft-tproxy` и `kmod-nft-fib`. Комплект для OpenWrt 24.10.8 ставит нужные скрипты в отдельный каталог без хуков запуска менеджера. Для уже настроенного стенда есть режим с проверкой установленных файлов. VPN Routing сверяет SHA-256 скрипта с закреплённой ревизией `10b4cb8` и использует отдельную таблицу `inet vpn_capture`. [Установка комплекта](../install/README.md), [Скрипт TPROXY Manager](https://github.com/rico-x/tproxy-manager/blob/10b4cb8afdd6db9ee8ce30f0532831e2c0e2a511/pkg/tproxy-manager/usr/bin/tproxy-manager.sh)

- Подписка загружается по HTTPS на порту 443. При первом добавлении источника LuCI просит подтвердить его точный домен. Подтверждение относится к этой ссылке, DNS проверяется и привязывается к публичным IPv4, HTTP-перенаправления отклоняются. VPN Routing читает строки `vless://`, `hysteria2://` и `hy2://` из обычного текста, Base64 или Base64url. Выход VLESS использует TLS или REALITY, Hysteria2 использует QUIC с TLS на одном UDP-порту. Для TLS Xray использует системные доверенные CA OpenWrt и проверяет имя сервера. Браузер получает имена и непрозрачные идентификаторы. Список живёт 30 минут в приватном каталоге роутера. [Поддерживаемые параметры и тестовые профили](../docs/transport-profiles.md)
- HEAD отправляется на контрольный HTTPS-адрес через временный Xray и SOCKS с одноразовым паролем на `127.0.0.1`. Проверяется принадлежность порта этому экземпляру Xray. В пробном конфиге есть только выбранный выход. Успех, прочие HTTP-ответы и таймаут показываются отдельно. По умолчанию контрольный адрес — `https://www.gstatic.com/generate_204`. [Параметры curl для SOCKS](https://curl.se/docs/manpage.html#--socks5-hostname)
- При подключении VPN Routing проверяет кандидат через `xray run -test`, запускает свой Xray через procd и проверяет HEAD через этот экземпляр. После этого включает защиту от прямого форвардинга (`inet vpn_guard`), применяет перехват (`inet vpn_capture`) и сохраняет ссылку, сервер и область перехвата. Для состояния «Подключено» проверяются локальные слушатели и обе таблицы.
- При сбое первого подключения VPN Routing пытается убрать свои правила и остановить свой Xray. При сбое восстановления таблица защиты остаётся активной. Если очистка не подтверждена, LuCI показывает «Сбой подключения» и оставляет доступной кнопку «Отключить». Она отменяет восстановление, снимает перехват, останавливает свой Xray и затем убирает защиту. Ссылка и сервер сохраняются до удаления подписки.
- При загрузке с сохранённым подключением VPN Routing ставит защиту до штатного запуска firewall4 и netifd. procd повторяет попытки с тем же сервером. Перехват включается после успешного HEAD. Защита использует отдельную таблицу и сохраняется при `fw4 reload`. Для блокировки требуется работоспособный nftables. Если раннее создание таблицы завершилось ошибкой, прямой выход возможен до успешной повторной установки защиты. [Порядок запуска firewall4](https://github.com/openwrt/firewall4/blob/master/root/etc/init.d/firewall) · [Порядок запуска netifd](https://github.com/openwrt/openwrt/blob/v24.10.8/package/network/config/netifd/files/etc/init.d/network#L1-L5)
- «Удалить подписку» удаляет сохранённую HTTPS-ссылку, её последний выбранный сервер и кэш. Действие доступно после отключения VPN Routing или при активном резерве. Для резерва предусмотрена своя кнопка «Удалить резерв».

### Идентификатор роутера

При первом открытии настроек или импорте подписки VPN Routing генерирует 128 случайных бит и хранит их как 32 шестнадцатеричных символа в `/etc/vpn-routing-hwid` с правами 0600. LuCI показывает это значение в настройках в поле для копирования. `sysupgrade` сохраняет файл при переносе настроек на новую версию системы.

При GET подписки с разрешённого HTTPS-источника VPN Routing посылает `x-hwid` и `x-device-os: OpenWrt`. Лимит устройств и отклонение HWID отображаются как ошибки импорта. [Контракт HWID Remnawave](https://docs.rw/features/hwid-device-limit/)

### Профиль перехвата

По умолчанию действует режим «Вся локальная сеть» на `br-lan`. Первое подключение доступно сразу после выбора сервера. VPN Routing учитывает входящий LAN-интерфейс и его настроенные IPv4-подсети. Устройства, подключившиеся к ним после запуска, попадают под перехват автоматически.

В режиме «Только выбранные устройства» добавьте нужные адреса из DHCP или введите IPv4 вручную. VPN Routing сверяет адреса с подсетью и исключает адрес роутера. Старые профили с `sources` и без `mode` сохраняют прежний список. Смена режима доступна при отключённом VPN Routing и вступает в силу при следующем подключении. [Интерфейсы netifd](https://openwrt.org/docs/guide-developer/ubus/network), [Список аренд LuCI](https://github.com/openwrt/luci/blob/openwrt-24.10/modules/luci-mod-status/htdocs/luci-static/resources/view/status/include/40_dhcp.js)

LuCI сохраняет политику в `/etc/vpn-routing/policy.json` от root с режимом 0600. Ручной профиль совместим с формой. Для загрузки подписки и HEAD профиль перехвата не нужен. Перехват рассчитан на IPv4 LAN с выключенным flow offload и без маршрута IPv6 по умолчанию. Защита действует для форвардинга IPv4 с выбранного интерфейса. В режиме списка она ограничена указанными адресами. Она пропускает обмен внутри LAN и служебные IPv4-диапазоны из исключений TPROXY. Трафик самого роутера, включая запросы его DNS-резолвера к вышестоящему серверу, настраивается отдельно. VPN Routing резервирует порт 61229, таблицы и приоритеты 21219/21220 и метки 0x10000000/0x20000000. [Пример ручного профиля](policy.example.json)

### Правила трафика

Основной способ получения правил — ответ самой подписки. Поддерживаются Happ `routing` и INCY `autorouting` в заголовках или теле списка серверов. В форме подключения появится выбор формата; при единственном предложении он выбран автоматически. «Подключить» проверяет и сохраняет профиль, привязывает его к этой подписке и применяет. Несколько форматов требуют явного выбора. При обновлении подписки повторно проверяется выбранный профиль, включая изменения правил при неизменной ссылке сервера. Сохранённые вручную правила имеют приоритет до явного выбора. [Доставка, обновление и ограничения](../docs/subscription-routing.md)

В ответе `settings` признак `routing.fromSubscription` обозначает профиль, связанный с подпиской. `routing.source` сохраняет конкретный формат `happ` или `incy`. «Убрать сохранённые правила» прекращает привязку; чтобы следующие подключения не импортировали предложения заново, выберите «Весь трафик через VPN» в форме подключения.

Карточка «Маршрутизация» разделяет активный режим через VPN, сохранённый профиль, применённые правила и состояние, в котором применение пока нельзя подтвердить. Раскройте «Действующие правила», чтобы увидеть условия блокировки, VPN и прямого выхода в порядке проверки. В этом же списке указан маршрут для перехваченного трафика без совпадений. Метка «применены» требует готового экземпляра Xray, действующего перехвата и защиты, совпадения рабочей конфигурации с сохранённым профилем.


Откройте «Ручной импорт Happ или INCY» и вставьте заголовки Happ либо заголовки и локальный JSON профиля INCY. После «Проверить профиль» LuCI покажет группы DIRECT, VPN и BLOCK. «Сохранить правила» проверяет конфигурацию через `xray run -test` и записывает скомпилированные правила. Если загрузка DAT или проверка отклоняет профиль, VPN Routing сохраняет прежнюю политику. Правила вступают в силу при следующем подключении. «Убрать сохранённые правила» возвращает для подходящего LAN-трафика маршрут через выбранный сервер.

Для вручную импортированного профиля с разрешёнными ссылками RoscomVPN кнопка сохранения загружает `geoip.dat`, `geosite.dat` и их `.sha256` по HTTPS. Поддерживаются версионные ссылки на оба утверждённых каталога `release` на jsDelivr. VPN Routing сверяет обе суммы и проверяет категории через Xray до сохранения правил. Проверенная пара хранится отдельно от штатных DAT Xray, сохраняется в sysupgrade и используется при следующем подключении. В карточке маршрутизации видно, загрузил ли её рабочий Xray. [Ресурсы Xray](https://xtls.github.io/en/config/env.html#resource-file-path)

Правила распространяются на выделенный LAN-вход. Явное правило DIRECT отправляет поток через Xray в обычную маршрутизацию роутера. BLOCK закрывает совпавший поток. VPN и трафик без совпадения идут через выбранный выход. Контрольный HEAD использует этот же выход независимо от правил. Для своей пары DAT можно указать хеши и разрешённые категории в расширенной политике. [Формат профиля и геоданные](../docs/routing-adapter.md)

### Локальный DNS

Карточка «Локальный DNS» показывает вышестоящие адреса, которые использует `dnsmasq` для запросов от LAN. Установка VPN Routing сохраняет существующий DNS OpenWrt. Для роутеров с DNSCrypt на `127.0.0.10` этот режим определяется автоматически. Другие варианты включают обычный Яндекс DNS, AdGuard DoH/DoT/DoQ, Cloudflare DoH/DoT и собственный сервер. [DNS в OpenWrt](https://openwrt.org/docs/guide-user/base-system/dhcp), [Яндекс DNS](https://dns.yandex.ru/), [AdGuard DNS](https://adguard-dns.io/en/public-dns.html), [Cloudflare DNS](https://developers.cloudflare.com/1.1.1.1/encryption/)

Для DoH, DoT и DoQ установщик VPN Routing подтягивает пакет `dnsproxy` из подписанного репозитория OpenWrt 24.10. Его штатная служба используется на `127.0.0.1:61230` после выбора зашифрованного профиля. Для своего сервера поддерживаются IPv4 и `IPv4#порт` либо адреса `https://…/dns-query`, `tls://…`, `quic://…`. Для первоначального разрешения имени зашифрованного сервера можно задать IPv4 bootstrap. [Пакет dnsproxy](https://openwrt.org/packages/pkgdata/dnsproxy)

«Проверить текущий DNS» выполняет контрольный запрос. «Сохранить и применить DNS» сначала проверяет новый сервер и затем применяет настройку сразу, в том числе при включённом VPN Routing. Выбранный сервер заменяет общие upstream-адреса dnsmasq с `noresolv=1`, а локальные записи и условные upstream сохраняются. При ошибке применения LuCI сообщает результат отката. Сложные внешние настройки можно просмотреть, а их редактирование остаётся в OpenWrt.

## Контракт сетевых обработчиков

Вызовы идут через авторизованный POST с токеном LuCI. Положительный ответ имеет `ok: true`. Запросы и ответы с URL подписки исключаются из журналов и кэшей.

| Действие | Параметры кроме токена | Положительный результат |
| --- | --- | --- |
| `status` | — | `state` со значением `disconnected`, `restoring`, `connected` или `degraded`. `hasSubscription` показывает наличие сохранённой или загруженной подписки, `hasSavedSubscription` — наличие сохранённого источника. Для выбранного сервера передаются `serverId`, `activeSource` со значением `subscription` или `reserve` и `serverName` при действующем подключении или восстановлении. `subscription` содержит `url`, `snapshot` и `servers`. Метка `savedOnly` обозначает сервер из сохранённой записи после потери списка. Поле `reserve` содержит `id`, `name` и `snapshot`. |
| `subscription` | `url`, опционально `confirmHost` | `snapshot` и `servers`. Список содержит до 256 пар `id`, `name`. `routingSources` содержит предложенные форматы `happ`/`incy`, `routingSource` — сохранённый выбор этой подписки, `hasManualRouting` — приоритет самостоятельного профиля. Эти поля доступны и внутри `status.subscription`. |
| `remove_subscription` | — | Статус с `hasSubscription: false`. Если используется сервер подписки, возвращается HTTP 409. |
| `save_reserve` | `name`, `link`, при замене `snapshot` | Статус с новым снимком резерва. |
| `remove_reserve` | `snapshot` | Статус после удаления резерва. При активном резерве или его восстановлении возвращается HTTP 409. |
| `connect` | `snapshot`, `server`, для переключения также `activeServer` с ID текущего узла; опционально `routingSource=happ/incy/none` | `state: "connected"` с `serverId` и `serverName` после сохранения и подтверждения применения. Если активный выбор изменился, возвращается HTTP 409 `connection_changed`. При нескольких форматах без сохранённого выбора — HTTP 409 `routing_choice_required`. |
| `disconnect` | — | `state: "disconnected"` после подтверждения отключения. |
| `probe` | `snapshot`, `server` | `serverId`, `method: "HEAD"` и `result`. Для `response` передаются `httpCode` и `elapsedMs`. Другие значения `result` — `timeout` и `unreachable`. |
| `settings` | — | `editable`, `networks`, `capture`, опциональные `routing.source` и `hwid`. `routing.managedGeo` означает пару проверенных геобаз. `routingStatus.state` принимает `applied`, `default`, `inactive` или `unverified`. Для сохранённого профиля `routingStatus.counts` содержит числа `proxy`, `direct`, `block`, а `routingStatus.rules` содержит проверенные `{tag, kind, values}` в рабочем порядке. |
| `save_capture` | `interface`, `mode`, `sources` для `selected` | Та же форма, что у `settings`. В режиме `all` поле `sources` отсутствует. Для `selected` принимается до 32 IPv4-адресов через пробельные символы. Запрос с `sources` без `mode` остаётся совместимым. |
| `save_routing` | `source`, `headers`, `policy`, `profile` для ручного импорта | Та же форма, что у `settings`. Запрос с одним `source=none` убирает сохранённые правила. |
| `dns_settings` | — | Действующие `profile`, `addresses`, наличие `encryptedAvailable` и возможность редактирования `configurable`. `system` обозначает внешнюю настройку OpenWrt. |
| `check_dns` | — | Тот же результат с `checked: true` после ответа на контрольный запрос. |
| `apply_dns` | `profile`, для `custom` также `address` и опционально `bootstrap` | Тот же результат после проверки и применения. При отказе возвращается код причины. |

Снимок привязывает действие к конкретной версии списка подписки или записи резерва. Серверная часть отклоняет устаревшие снимки и неизвестные идентификаторы. Пока операция выполняется или откатывается, `status` возвращает HTTP 409. Это сохраняет блокировку кнопки, если браузер запрашивает статус после таймаута.

## Сборка и проверка

~~~sh
python3 luci/build-ipk.py /path/to/output
~~~

Укажите существующий каталог вывода. Скрипт создаёт `luci-app-vpn-routing_0.3.12-1_all.ipk` в формате OpenWrt 24.10. Установка пакета оставляет перехват выключенным. Перед обновлением или удалением отключите VPN Routing в LuCI, в том числе если он ожидает восстановления. Тесты контроллера проверяют авторизацию, CSRF, поля запросов и совпадение предпросмотра с CLI. Сценарии Lua 5.1 в `tests/*.test.lua` покрывают загрузку подписки, проверку HEAD, конфликт перехвата и порядок сохранения и отката.
